# Benchmark de Centros de Ayuda y Documentación SaaS

## 1. Objetivo
Investigar y analizar cómo estructuran sus centros de ayuda y documentación cuatro referentes de software contable y de gestión SaaS (**Siigo**, **Alegra**, **Holded** y **Contoda**), identificando la organización de sus categorías, recursos visuales, flujo de navegación y manejo de errores, con el fin de extraer buenas prácticas a replicar en nuestro sistema.

---

## 2. Análisis por Referente

### 2.1 Siigo

#### Descripción general
El Centro de Ayuda de Siigo organiza la documentación por productos y módulos funcionales. La navegación está diseñada para que los usuarios encuentren rápidamente la información mediante un buscador principal, categorías jerárquicas y artículos paso a paso apoyados con recursos visuales.

#### Organización de categorías
* **Nivel 1 (Productos):** Siigo Nube, Nómina Electrónica Nube, Siigo Facturación, Contador Nube, Siigo Pyme Windows, Otros Productos.
* **Nivel 2 (Módulos):** Generalidades, Configuración general, Saldos iniciales, Procesos de compras, Procesos de ventas, Inventarios, Activos fijos, Informes financieros y contables, Otros informes, Otros procesos.
* **Nivel 3 (Artículos):** Registro comprobante contable, Cierre de año, Cierre de cuentas de impuestos y otras cuentas por tercero, Ver más...

*Estructura jerárquica:* `Producto → Módulo → Artículo`

#### Navegación
| Elemento | Descripción |
| :--- | :--- |
| **Buscador principal** | Visible en la parte superior de todas las páginas para localizar artículos rápidamente. |
| **Menú superior** | Permite cambiar entre los diferentes productos de Siigo. |
| **Menú lateral** | Organiza los artículos por módulos funcionales. |
| **Categorías de acceso rápido** | Preguntas Frecuentes, Primeros Pasos, Facturación Electrónica, Nómina Electrónica y Capacitaciones. |
| **Listado de artículos** | Cada categoría muestra los artículos disponibles mediante tarjetas o listas. |
| **Botón "Ver más"** | Permite acceder a más artículos dentro de una categoría. |

#### Recursos visuales
| Recurso | Uso | Observaciones |
| :--- | :---: | :--- |
| **Capturas de pantalla** | ✅ Sí | Explican visualmente cada paso del proceso. |
| **GIF animados** | ✅ Sí | Se utilizan para mostrar procesos dentro de la aplicación. |
| **Videos** | ✅ Sí | Videos incrustados desde YouTube para procesos completos. |
| **Flechas e indicadores** | ✅ Sí | Señalan botones y opciones importantes. |
| **Imágenes ilustrativas** | ✅ Sí | Complementan la explicación de cada procedimiento. |
| **Tablas** | ⚠️ Pocas | Solo cuando el contenido lo requiere. |
| **Alertas o notas** | ⚠️ Ocasionalmente | Para recomendaciones importantes. |

#### Estructura de los artículos
* Título del procedimiento.
* Descripción breve.
* Video introductorio (cuando aplica).
* Instrucciones paso a paso.
* Capturas o GIF de apoyo.
* Explicación adicional.
* Enlaces relacionados o artículos complementarios.

#### Manejo de errores
Siigo dispone de una sección de Preguntas Frecuentes donde reúne problemas comunes (ej. problemas al iniciar sesión, eliminar caché del navegador, mejorar el rendimiento de la plataforma, solucionar el modo de solo consulta). Cada artículo explica:
* El problema.
* La causa probable.
* Los pasos para solucionarlo.

### 2.2 Alegra

#### Descripción general
El Centro de Ayuda de Alegra organiza su documentación por productos y áreas funcionales. Cada artículo mantiene una estructura uniforme con índice interno, recursos multimedia y enlaces entre artículos, facilitando la navegación y el aprendizaje progresivo.

#### Organización de categorías
* **Nivel 1 (País):** Colombia, México, República Dominicana, Costa Rica, España, Panamá, Perú, Argentina, Venezuela.
* **Nivel 2 (Productos):** Alegra Contabilidad, Alegra Nómina, Alegra POS, Alegra CRM, App Móvil, Alegra IA, MCP, Contabilidad Inteligente, Sector Salud, Migraciones, Integraciones, Alianzas Académicas, Espacio Contador, Planes y Suscripciones, Solo Facturación, Casos de uso.
* **Nivel 3 (Artículos):** Secciones específicas según la guía (ej. *¿Cómo iniciar contablemente en Alegra? Guía paso a paso*).

*Estructura jerárquica:* `País → Producto → Artículo → Secciones internas`

#### Navegación
| Elemento | Descripción |
| :--- | :--- |
| **Buscador principal** | Visible desde la página principal para localizar artículos rápidamente. |
| **Selector de país** | Permite acceder a documentación específica según la normativa de cada país. |
| **Menú lateral** | Organiza los artículos por productos y módulos. |
| **Breadcrumb** | Indica la ubicación actual del usuario (Ej.: `Colombia > Contabilidad Inteligente`). |
| **Índice interno** | Cada artículo incluye un índice con enlaces a las diferentes secciones. |
| **Botón para volver arriba** | Facilita la navegación en artículos extensos. |

#### Recursos visuales
| Recurso | Uso | Observación |
| :--- | :---: | :--- |
| **Capturas de pantalla** | ✅ Sí | Se utilizan para complementar algunos procedimientos. |
| **Videos** | ✅ Sí | Videos incrustados desde YouTube para explicar procesos completos. |
| **GIF animados** | ⚠️ No observados | No se observaron en el artículo analizado. |
| **Índice interactivo** | ✅ Sí | Permite navegar rápidamente entre las secciones del artículo. |
| **Hipervínculos** | ✅ Sí | Conectan con otros artículos relacionados y conceptos del sistema. |
| **Botón flotante** | ✅ Sí | Permite regresar al inicio del artículo. |

#### Estructura de los artículos
* Título del procedimiento.
* Introducción.
* Índice con enlaces internos.
* Explicación conceptual.
* Video explicativo (cuando aplica).
* Desarrollo paso a paso.
* Enlaces a otros artículos relacionados.
* Valoración del artículo.

#### Manejo de errores
No se observó una sección exclusiva para errores dentro del artículo analizado. Sin embargo, la documentación utiliza enlaces internos para dirigir al usuario hacia otros procedimientos relacionados cuando es necesario ampliar la información o resolver una situación específica.

### 2.3 Holded

#### Descripción general
El ecosistema de soporte y documentación de Holded combina un centro de ayuda estructurado por funciones, un hub de recursos educativos (*Academy, Webinars, Glosario, Guías*) y una sección dedicada a desarrolladores con documentación técnica de API e integraciones (como servidor MCP).

#### Organización de categorías
* **Nivel 1 (Recursos / Hubs):** Funcionalidades, Recursos (Developers, Directorio, Migración, Academy, Webinars, Guías, Blog, Glosario, Magazine), Sobre Nosotros, Legal.
* **Nivel 2 (Módulos / Funciones):** ERP, Programa de contabilidad, Programa de facturación, Programa de tesorería, Inventario, Equipo / RR. HH., CRM.
* **Nivel 3 (Secciones y Referencias de API):**
  * *Contabilidad:* Contabilidad, Cuentas de gastos, Pagos, Compras, Impuestos.
  * *Tesorería:* Cuentas bancarias, Métodos de pago, Remesas, Previsiones de facturación.
  * *Guías:* Primeros pasos, Autenticación, Paginación, Gestión de errores, Límites, Webhooks, Servidor MCP.

#### Navegación
| Elemento | Descripción |
| :--- | :--- |
| **Buscador global rápido** | Incorpora buscador rápido accesible con atajo de teclado (`Buscar ⌘K`). |
| **Menú superior y Footer extendido** | Enlaces estructurados para acceder a funcionalidades, recursos y soporte. |
| **Menú lateral desplegable** | Organiza guías y referencias por módulos (*Contabilidad*, *Tesorería*) en la documentación técnica. |
| **Desplegables (Acordeón)** | Utilizados en la sección de Preguntas Frecuentes para una lectura limpia sin recargar la página. |
| **Badges y contadores** | Muestra etiquetas contextuales (*"v1.0.0"*, *"Nueva API"*, *"28 endpoints"*) para orientar la navegación. |

#### Recursos visuales
| Recurso | Uso | Observación |
| :--- | :---: | :--- |
| **Tarjetas (Grid layout)** | ✅ Sí | Organizan visualmente cada función, módulo o guía con un icono descriptivo. |
| **Consolas de código / API** | ✅ Sí | Estilo *Dark mode* con sintaxis resaltar e indicadores de estado HTTP (`200 OK`, `201 Created`). |
| **Banners de aviso / Callouts** | ✅ Sí | Destacan versiones anteriores u obsoletas, así como novedades importantes. |
| **Iconos informativos** | ✅ Sí | Acompañan cada categoría (cohetes, candados, enlaces, advertencias). |

#### Estructura de los artículos y FAQ
* **Preguntas Frecuentes:** Pregunta clara en formato acordeón que se despliega al hacer clic mostrando la solución o explicación de la normativa/función.
* **Guías de API y Funciones:** Título del módulo, resumen explicativo, badges de requisitos, bloques visuales de código o ejemplos de integración, y tarjetas con temas relacionados.

#### Manejo de errores
Holded cuenta con una sección explícita dedicada a la **Gestión de errores** dentro de sus guías (*Códigos de estado HTTP y gestión de errores*). Además, aborda dudas sobre errores comunes y normativa dentro de su módulo de Preguntas Frecuentes y en las guías específicas de modelos/impuestos.

### 2.4 Contoda

#### Descripción general
Contoda estructura su soporte orientándose fuertemente a las soluciones por módulo funcional y casos de uso por tipo de comercio. Organiza las dudas frecuentes en una interfaz limpia basada en acordeones e integra recursos educativos bajo su sección de "Comunidad" y "Aprende Contoda".

#### Organización de categorías
* **Nivel 1 (Menú Principal / Footer):** Servicios, Planes, Comunidad (Aprende Contoda, Blog, Testimonios), Contacto, Más (Preguntas frecuentes, Términos y condiciones, Política de privacidad).
* **Nivel 2 (Módulos / Productos):** Software Punto de Venta (POS), POS Electrónico, Control de Inventarios, Facturación Electrónica DIAN, Nómina Electrónica, Cierre de Caja, Compras y Pagos, Informes.
* **Nivel 3 (Sectores / Casos de uso):** Clasificación por tipología de negocio (Pet Shop, Belleza, Tecnología, Ferreterías, Pañalera, Papelería, Minimarkets, Tiendas de ropa, Autopartes, Veterinaria, E-commerce, Peluquería-Spa, Tiendas Naturistas).

#### Navegación
| Elemento | Descripción |
| :--- | :--- |
| **Menú superior desplegable** | Organiza enlaces rápidos a servicios, planes y comunidad. |
| **Footer navegable** | Agrupa en columnas los productos, recursos y enlaces legales/soporte. |
| **Preguntas Frecuentes (Acordeón)** | Secciones desplegables interactivas con signo `+ / -` para leer respuestas sin cambiar de vista. |
| **Filtros por tipo de comercio** | Tarjetas interactivas con emojis para guiar la navegación según la actividad del usuario. |
| **Call to Action (CTA) flotantes** | Botones directos de "Agendar Demostración" y "¿Te llamamos?". |

#### Recursos visuales
| Recurso | Uso | Observación |
| :--- | :---: | :--- |
| **Tarjetas Grid con Emojis/Iconos** | ✅ Sí | Representación clara y amigable de cada tipo de comercio o funcionalidad. |
| **Mockups de Interfaz** | ✅ Sí | Muestran capturas reales del dashboard y tablas de inventario en la plataforma. |
| **Videos de Testimonios / Casos de Éxito** | ✅ Sí | Casos reales en formato de video corto para generar confianza. |
| **Bloques de Métricas / Social Proof** | ✅ Sí | Tarjetas con indicadores contables (ej. empresas vinculadas, usuarios, contadores). |

#### Estructura de los artículos y FAQ
* **Preguntas Frecuentes:** Estructura directa de Pregunta (Título) → Respuesta explicativa desplegable.
* **Formatos de respuesta:** Incluyen aclaraciones operativas (ej. periodo de prueba de 15 días, soporte ilimitado, normas sobre montos para emisión de factura electrónica).

#### Manejo de errores
El manejo de dudas e incidencias comunes se concentra en la sección de **Preguntas Frecuentes**, abarcando temas de configuración de hardware (lectores de código de barras, cajas registradoras), soporte técnico ilimitado y cumplimiento de normativas fiscales (límites de facturación).

## 4. Conclusiones y Buenas Prácticas a Replicar

A partir de la revisión de **Siigo**, **Alegra**, **Holded** y **Contoda**, se definen las siguientes buenas prácticas clave para el diseño y estructuración de nuestro centro de ayuda:

### 1. Navegación y Arquitectura de Información
* **Buscador global con atajo de teclado:** Mantener una barra de búsqueda visible (con soporte para `⌘K` / `Ctrl+K`) para facilitar la localización rápida de artículos (práctica de Siigo, Alegra y Holded).
* **Menú Lateral Persistente y Breadcrumbs:** Incorporar navegación lateral estructurada por módulos y breadcrumbs para evitar que el usuario pierda su contexto (práctica de Alegra y Holded).
* **Segmentación por Tarjetas y Casos de Uso:** Implementar vistas en rejilla (*grid*) con iconos para explorar módulos o sectores de negocio (práctica de Holded y Contoda).

### 2. Estructura de Contenido y Usabilidad
* **Desplegables (Acordeón) para FAQs:** Utilizar componentes expandibles `+ / -` para resolver dudas frecuentes sin recargar ni saturar la página (práctica de Holded y Contoda).
* **Índice Interno (ToC):** Incluir enlaces de salto directo en artículos extensos para mejorar la lectura rápida (práctica de Alegra).
* **Estandarización de Artículos:** Seguir una plantilla homogénea: `Título → Objetivo/Prerrequisitos → Paso a Paso (con imágenes/GIFs) → Solución de Errores → Temas Relacionados`.

### 3. Recursos Visuales y Manejo de Errores
* **Apoyo Multimedial Diverso:** Combinar capturas de pantalla con llamadas de atención, GIFs para micro-interacciones, mockups de interfaz y consolas o bloques visuales para configuraciones técnicas.
* **Módulo Dedicado a Resolución de Errores:** Incluir guías o tablas específicas de *Problema → Causa → Solución Paso a Paso* para desacoplar las consultas operativas del canal de soporte (práctica de Siigo y Holded).
* **Bloques de Aviso y Badges:** Implementar etiquetas de estado y cajas *Callout* de colores para diferenciar recomendaciones, avisos de versiones o advertencias importantes.
* **Widget de Valoración:** Agregar un sistema de feedback (*"¿Te resultó útil este artículo?"*) al final de cada publicación para monitorear y actualizar constantemente la documentación.
